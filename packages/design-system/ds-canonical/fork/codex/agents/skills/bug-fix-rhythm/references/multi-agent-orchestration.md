# 多代理批次工作 —— 原則與對照組做法

> `/bug-fix-rhythm` 的 reference。**流程本身不住這裡**:一次工作拆成多包、分給不同代理實作與審查時,怎麼實作、怎麼審查、審查幾輪、何時再修、合回怎麼走,只照 `node_modules/@qijenchen/design-system/ds-canonical/rules/work-process.md`;本檔不重述步驟、輪數或數字。
> 本檔只收那份流程之外、多個代理同時動工才會撞到的 9 條原則。每條附「對照組怎麼做」:證明這條真的守得住的兩面量法 —— 違反時要紅、照做時要綠,只量到一面不算守住。
> 數值門檻(全機同時跑的重工作條數、負載上限、等候上限等)不寫在 repo,由該批工作的狀態檔訂(design system repo 自己的批次工作:見交接 `state/schedule.json` 的 `settings`)。

## 1. 工作狀態只有一個來源,其他都是視圖

- **原則**:每包還剩什麼、在等誰、證據在哪,只記在一份狀態檔;給人看的摘要與清單都由它產生,不手改、不另記一份。
- **對照組**:手改產生出來的視圖一個字,重新產生後比對要不同(紅);沒動過就相同(綠)。

## 2. 每個「完成」都綁定量過的那一份內容

- **原則**:「做完 / 驗過 / 綠」要帶著被量那一份內容的指紋(commit 或 tree);內容變了就是還沒量,要重量,不能沿用舊結果。
- **對照組**:量完之後改一個字,拿舊的綠去判新內容,必須判成「待重量」;內容沒變才准沿用。

## 3. 儀器先證明會紅;量不到 = 儀器失效;本機量的就是 CI 要的

- **原則**:新檢查先在「修正前的內容」(或刻意注入一個違規)跑出紅,再在修正後跑出綠。跑不起來、0 筆、逾時記「儀器失效」,不記綠(`node_modules/@qijenchen/design-system/ds-canonical/rules/meta-patterns.md` M37:「沒觀察到」不等於「沒發生」)。本機要跑的檢查清單從 CI 設定導出,不手抄第二份。
- **對照組**:同一支檢查在修正前、修正後各跑一次,紅綠兩面都留結果;在 CI 設定加一個必紅的步驟,本機導出的清單也要跟著紅。

## 4. 機器承載有上限

- **原則**:安裝、建置、整套 hook 測試、瀏覽器閘這類重工作,全機同時在跑的條數有上限,負載超過上限就排隊、不開新的;數值見文首。等候逾時記「儀器失效」,不記成產品紅。
- **對照組**:同時送出比上限多一條的重工作,多出來那條要排隊,前面放號後才開始;已經持號的整串裡面的子步驟不重複拿號(不會自己把自己卡死)。

## 5. 交接不截斷、對帳歸零

- **原則**:每一筆未結 —— 各包回報的沒做完項目、user 追問、承諾、更正 —— 都要有指派或處置;交接時不摘要掉。
- **對照組**:把所有回報裡的未結清單跟狀態檔對帳,差集必須是 0;刪掉其中一筆再對帳,要紅。

## 6. 該誰決定、該等誰,照規則

- **原則**:前置沒滿足的包不開工。要 user 決定的只限共同 bootstrap「# 自主執行 canonical」canonical-decision-authority 區塊列的類別,其餘工程判斷自己收斂。寫的人不審:規格核對由沒參與實作的人做(`node_modules/@qijenchen/design-system/ds-canonical/rules/work-process.md`「每一包」第 2 點)。
- **對照組**:拿前置還沒合回的包去派工,要被擋下;派工前把每個「要 user 決定」的項目對一次類別,類別外的要被判回工程自決。

## 7. 同一族根本原因第二次出現,就停下重新設計

- **原則**:同一類問題第二次冒出來(不論是不是同一包),代表上一層沒抓住:停下找根因、先補強制面(閘或測試),不再逐題補表面。審查輪數、之後什麼才再修,照 `node_modules/@qijenchen/design-system/ds-canonical/rules/work-process.md`,本檔不另訂第幾輪。
- **對照組**:把已修過的必修按根因歸族;某一族第二次出現時,下一步必須是改設計或補閘(該次 commit 帶新的閘或測試,且新閘在修正前的內容上會紅),不是又一個同形狀的表面修正。

## 8. 規則有住處、有執行面

- **原則**:新紀律寫進 repo 的 owner 檔,並接上一個真的會跑它的執行面(CI、hook 或腳本);只寫在散文、交接資料夾或個人記憶裡 = 沒落地。交接資料夾只放那一批的狀態與指向住處的指標(`node_modules/@qijenchen/design-system/ds-canonical/rules/work-process.md`「適用」段)。
- **對照組**:拿掉閘的呼叫點,檢查要紅(design system repo 的 gate-reachability-invariant 就是守「寫了閘卻沒有任何執行面呼叫它」這一面)。

## 9. 攤薄固定驗證成本

- **原則**:同一份內容只量一次(指紋相同就沿用,見第 2 條);便宜的檢查先跑,前段紅了就停;收窄的檢查子集只在兩面驗過、補跑整套 0 漏之後才用在單包;整套由合回點推送後的 CI 跑(`node_modules/@qijenchen/design-system/ds-canonical/rules/work-process.md`「合回點」)。
- **對照組**:收窄子集與整套在同一份內容上各跑一次,結果要相同(0 漏)才准用;同一個指紋第二次送量,要直接沿用,不重跑。
